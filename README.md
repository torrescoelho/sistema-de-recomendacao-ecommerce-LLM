# 📚 Recommendation System for E-commerce with Language Models

An intelligent recommendation system for e-commerce platforms that uses Transformer-based language models (LLMs), such as BERT, to understand natural-language requests and suggest relevant books based on semantic embeddings.

Final project of the Bachelor's degree in Computer Engineering (UTAD, 2025). The catalogue comes from [Books to Scrape](https://books.toscrape.com/), a simulated shop created for practising *web scraping*; purchases and user feedback are **simulated**.

---

## 🧭 Overview

The user writes what they are looking for (for example, *"I want a mystery book"*) and the system:

1. interprets the request and detects the most likely category;
2. filters the catalogue by category, rating and price;
3. compares the request with each book through semantic embeddings;
4. refines and diversifies the results;
5. returns the recommendations with an explanation and tags.

## ✨ Features

- Multilingual semantic search (requests in Portuguese, catalogue in English)
- Optional filters by category and price
- Explanation and tags for each recommendation
- Feedback logging (1 to 5 stars or like/dislike) and interaction history lookup
- Documented REST API (Swagger) and console chatbot
- Comparative offline evaluation with statistical significance tests

## ▶️ Execution order

### 1. `scraper.py`
```bash
python scraper.py
```
Collects the book data from the online source and stores it locally for later processing. It generates two main files:
- `dados/livros.csv` (detailed book information)
- `dados/feedbacks.csv` (simulated purchases and user feedback)

### 2. `preprocessamento.py`
```bash
python preprocessamento.py
```
Cleans, normalises and prepares the collected data, making it suitable for analysis and modelling (includes TF-IDF vectorisation and the creation of derived features, such as seasonality, loyalty, average value and interval between purchases). The processed data is saved in:
- `dados/livros_limpos.csv` (cleaned and normalised data)
- `outputs_p/` (data files ready for analysis and modelling)

### 3. `analise.py`
```bash
python analise.py
```
Performs the exploratory data analysis, identifying patterns, trends and characteristics relevant to the recommendation system. It produces reports and visualisations that are saved in:
- `outputs_a/` (charts, tables and exploratory analysis reports)

### 4. `download_model.py`
```bash
python download_model.py
```
Downloads the pre-trained model required for the natural-language recommendation stages.

### 5. `modelo.py`
```bash
python modelo.py
```
Uses the prepared data and the downloaded model to *fine-tune* multilingual BERT for sentiment classification of the feedback (negative, neutral, positive), and evaluates the result (accuracy, F1 and confusion matrix). The training and evaluation results are saved in:
- `resultados/` (fine-tuned model, metrics and evaluation outputs)

### 6. API (`api/main.py`)
```bash
python -m uvicorn api.main:app --reload
```
Starts the API that exposes the recommendation system for external use, allowing real-time recommendation requests. The interactive documentation is available at `http://127.0.0.1:8000/docs`. It must stay running in one terminal while step 8 is executed.

### 7. `testes/teste_offline_ab.py`
```bash
python testes/teste_offline_ab.py
```
Runs the comparative offline test between the traditional system and the language-model system, using the data and models prepared in the previous steps. The test results are displayed in the terminal.

### 8. `bot.py`
```bash
python bot.py
```
Runs the chatbot that interacts with the API, making interaction easier for end users. It must be run **in another terminal**, with the API (step 6) running.

> **Notes**
> - The simulated feedback from step 1 is randomly generated, so each run produces slightly different data and, consequently, different results in the following steps. Occasional network failures during scraping are reported in the terminal and the process continues.
> - Step 5 uses a lot of RAM. Close other applications during training and, if a memory error occurs, reduce the batch size (`per_device_train_batch_size`) in `modelo.py`.
> - If the `resultados/` folder does not exist, the API works but skips the sentiment analysis.
> - On the first run of the API, the models are downloaded and the book embeddings are computed, which can take a few minutes.
> - If you change the dataset, delete `cache/embeddings_cache.pkl` so that the embeddings are recomputed.

## 📊 Evaluation and results

The comparison between the traditional system (popularity and category preferences) and the language-model system was carried out **offline**, with simulated data and a temporal split. No real A/B test was carried out.

| Metric | Traditional | Language models |
|---|---|---|
| Precision | 0.014 | 0.011 |
| Recall | 0.018 | 0.015 |
| F1 | 0.016 | 0.013 |
| Hit rate | 0.130 | 0.110 |

These values correspond to the run documented in the project report; a new run may give different values, since the simulated feedback is randomly generated.

The paired t-test and the Wilcoxon test indicate that the differences are **not statistically significant** (p > 0.8), so it is not possible to claim that one system is better than the other. Classic metrics only reward books that match the history and do not measure novelty or diversity.

## ⚠️ Known limitations

**Technical**
- The quality of the recommendations depends on the available historical data.
- Per-user personalisation is not implemented: the profile and history are stored, but they do not influence the ranking, which depends on the request (semantic search, filters and diversification by category).
- Limited explainability of the embedding-based recommendations.

**Methodological**
- The evaluation is based on simulated offline data; validation with real users in a production environment is needed.
- Historical data may become outdated in the face of emerging trends.
- The feedback collected is recorded, but it is not used to retrain the model nor integrated in real time.
